## Punch list (by severity)

### Critical — kills or hides the tool

**C1. rtl-airband-airband (MA mode) is alive but not publishing.**
PID 40974 started 17:52:30, but `/run/rtl_airband_airband_stats.txt` is from 17:37 — i.e. stats file predates the current process. Icecast `/status-json.xsl` confirms `ANALOG.mp3` source is empty (listeners are being served the silent `keepalive-analog.mp3` fallback). Same likely for `/ANALOG_GROUND.mp3`. Journal shows three SIGINT → SIGTERM-timeout → SIGKILL cycles between 17:48 and 17:52 (systemd "stop-sigterm timed out, killing"), so the binary doesn't shut down cleanly under stop, and after the last forced restart it isn't publishing. **Root cause hypothesis:** MA-mode rtl_airband boots, opens sdrplay API, but the output thread that writes stats + pushes to icecast never reaches steady state. There's also a `sdrplay_apiService` segfault in dmesg at 17:34:09 right before this episode — sdrplayd may have come back partially broken.
**Severity:** Critical (this is the wedge headline; no actual airband audio is reaching listeners).
**Fix scope:** investigate — start by `journalctl -u sdrplay -u rtl-airband-airband --since '17:30'` correlated, check if the MA-mode rtl_airband binary has a known stats-write deadlock, consider adding a stop-sec timeout shorter than the systemd default so the kill cascade is bounded.

**C2. dumpvdl2 service flap loop — 296 restarts.**
`NRestarts=293+`. Config wants `VDL2_RTL_SERIAL=VDL2A001` (from `/etc/airband-ui.conf`), but no dongle with that serial is plugged in — `lsusb` shows 5 RTL-SDRs (61108285, 70613472, 83241970, 45469635, 80000003) and zero `VDL2A001`. Process re-execs every ~5 s, log spam every 5 s, journald cost. Per `broker_policy.json` VDL2 was supposed to live on a dedicated dongle that isn't in the rig; ACARS hand-off is configured to share 61108285 but only when sounding mode is on (currently `false`).
**Severity:** Critical (background log flood, hides real errors, contributes to journald growth).
**Fix scope:** 1-line — either `systemctl disable --now dumpvdl2` until a dedicated dongle is in the rig, or point `VDL2_RTL_SERIAL` at a real serial.

### High — degrades reliability or hides truth

**H1. Heartbeat 0.25 s socket-read timeout still swallows real MP3 frames.**
`ui/handlers.py` `_heartbeat_sample_mount_bytes` still calls `sock.settimeout(0.25)` and breaks on the first `socket.timeout`. Verified empirically: an 8 s curl of `/DIGITAL.mp3` pulled 60 200 B and `/VFO.mp3` 29 400 B, but the heartbeat consistently reports `0 B in 0.7s`. So DIGITAL.mp3 and VFO.mp3 are flagged warn on every heartbeat even when the audio path is healthy. ANALOG row is correct in this case (source really is missing) so the false-positive isn't masking C1 today, but at lower digital traffic, low-bitrate genuine output will be classified as warn.
**Severity:** High (false yellows make the dashboard untrustworthy).
**Fix scope:** 1-hour — raise per-read timeout to ≥ 1.0 s and continue the loop on partial timeouts instead of breaking, or replace short-window byte sampling with the icecast `status-json` source check (which is already trusted for ANALOG.mp3).

**H2. `is-enabled` not considered before flagging "inactive" as warn.**
`extended_service_units` in `handlers.py` (lines ~3130-3160) loops services and flips warn the moment `_unit_active_cached` returns False. `acarsdec` and `radiosonde-auto-rx` are `systemctl is-enabled = disabled` — intentionally off — but the dashboard reports them yellow. `scanner-vlc-vfo` is also `disabled` and flagged warn for the same reason.
**Severity:** High (three permanent false yellows; trains the operator to ignore the row).
**Fix scope:** 1-hour — pull `systemctl is-enabled` (or check `LoadState=masked`/`UnitFileState`) and, when the unit is `disabled` or `masked`, report `"intentionally off" / status=ok`.

**H3. `disco.mp3` mount has no source in MA/SL split mode.**
`/etc/icecast2/icecast.xml` keeps the `/disco.mp3` mount with `fallback-mount=/keepalive-analog.mp3`. `disco/src/listen.py` only emits the `disco_mixer` block when `build-combined-config.py` runs in single-combined-mixer mode. Current mode is MA/SL split (two rtl-airband units, each with its own runtime conf), so the disco mixer is never added — listeners on `/disco.mp3` get the keepalive silence. Regression from the split-mode migration, not by design.
**Severity:** High (silent UX failure; mount is advertised but useless).
**Fix scope:** 1-hour — either remove the mount from `icecast.xml` for split mode or restore the disco publisher path in the ground rtl-airband unit (the natural home in split mode).

**H4. `/var/log/op25/op25.log` = 182 MB, no rotation.**
No logrotate config in `/etc/logrotate.d/` matches op25. Single growing file. Icecast2 rotates fine.
**Severity:** High (slow disk-eater; will eventually wedge the box).
**Fix scope:** 1-line — add `/etc/logrotate.d/op25` (weekly, rotate 4, compress, copytruncate since op25 holds the FD).

**H5. journald has no `SystemMaxUse` set.**
`/etc/systemd/journald.conf` has it commented out. Currently 2.7 G; default cap is 10 % of /var (~23 G) — fine for now but unbounded. With dumpvdl2 spamming, this fills faster.
**Severity:** High (latent; becomes Critical once disk pressure rises).
**Fix scope:** 1-line — set `SystemMaxUse=2G` in a drop-in.
